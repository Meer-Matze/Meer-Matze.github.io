# 图的表示

下文默认使用有向图，顶点编号为 $0$ 到 $V-1$，其中 $V$ 为顶点数，$E$ 为边数。

无向边 $(u,v)$ 可以表示为两条有向边：$u\to v$ 和 $v\to u$。对于邻接表和链式前向星，无向图中每条无向边因此需要存储两条有向边。

下文默认讨论**不含重边的图**。若允许重边，邻接表和链式前向星可以直接存储多条相同的边，而邻接矩阵需要使用计数或其他结构，不能仅用 $0$ 和 $1$ 表示边的存在性。

## 复杂度概览

| 表示方式   | 空间复杂度 | 查询边 $(u,v)$ | 遍历顶点 $u$ 的邻接点 |
| ---------- | ---------- | -------------- | --------------------- |
| 邻接矩阵   | $O(V^2)$   | $O(1)$         | $O(V)$                |
| 邻接表     | $O(V+E)$   | $O(\deg^+(u))$ | $O(\deg^+(u))$        |
| 链式前向星 | $O(V+E)$   | $O(\deg^+(u))$ | $O(\deg^+(u))$        |

其中，$\deg^+(u)$ 表示顶点 $u$ 的出度，即以 $u$ 为起点的边数。对于无向图，可以将其理解为顶点的度数。

邻接表和链式前向星查询边 $(u,v)$ 时，都需要遍历 $u$ 的出边，检查是否存在终点为 $v$ 的边。

## 邻接矩阵

邻接矩阵使用二维数组 `adj_matrix[u][v]` 表示边 $u\to v$ 是否存在。

对于不含重边的图，可以使用 $0$ 表示不存在边，使用 $1$ 表示存在边。

```cpp
struct GraphAdjMatrix {
    int vertex_count;          // 顶点数
    int edge_count = 0;        // 边数
    std::vector<std::vector<int>> adj_matrix;

    GraphAdjMatrix(int v)
        : vertex_count(v), adj_matrix(v, std::vector<int>(v, 0)) {}

    void addEdge(int u, int v) {
        if (adj_matrix[u][v] == 0) {
            adj_matrix[u][v] = 1;
            edge_count++;
        }
    }
};
```

邻接矩阵的优点是查询边是否存在的时间复杂度为 $O(1)$，实现简单；缺点是空间复杂度为 $O(V^2)$，当图比较稀疏时会浪费大量空间。

## 邻接表

邻接表为每个顶点维护一个容器，存储从该顶点出发的所有边的终点。

```cpp
struct GraphAdjList {
    int vertex_count;          // 顶点数
    int edge_count = 0;        // 边数
    std::vector<std::vector<int>> adj_list;

    GraphAdjList(int v) : vertex_count(v), adj_list(v) {}

    void addEdge(int u, int v) {
        adj_list[u].push_back(v);
        edge_count++;
    }
};
```

邻接表只存储实际存在的边，因此空间复杂度为 $O(V+E)$，适合表示稀疏图。

遍历顶点 $u$ 的所有出边时，只需要遍历 `adj_list[u]`，时间复杂度为 $O(\deg^+(u))$。

### 链式前向星

链式前向星使用数组模拟邻接表，适合需要高效遍历边的场景。

`head[u]` 存储顶点 $u$ 的第一条出边的编号，`next` 将同一出发点的边串联起来。边编号用于访问边数组中的元素，而不是表示顶点编号。

```cpp
struct GraphForwardStar {
    int vertex_count;          // 顶点数
    int edge_count = 0;        // 已存储的有向边数

    struct Edge {
        int to;                // 终点
        int next;              // 同一出发点的下一条边
    };

    std::vector<Edge> edges;
    std::vector<int> head;

    GraphForwardStar(int v) : vertex_count(v), head(v, -1) {}

    void addEdge(int u, int v) {
        edges.push_back({v, head[u]});
        head[u] = edge_count++;
    }

    // 添加一条无向边，并存储对应的两条反向有向边。
    void addUndirectedEdge(int u, int v) {
        addEdge(u, v);
        addEdge(v, u);
    }

    GraphForwardStar transpose() const {
        GraphForwardStar result(vertex_count);

        for (int u = 0; u < vertex_count; u++) {
            for (int i = head[u]; i != -1; i = edges[i].next) {
                result.addEdge(edges[i].to, u);
            }
        }

        return result;
    }
};
```

添加边时，新边的 `next` 指向原来的第一条出边，然后将 `head[u]` 更新为新边的编号。因此，**后加入的边会优先被遍历**。

这里的 `edge_count` 表示存储的有向边数。对于一条无向边，调用 `addUndirectedEdge` 会使其增加 $2$。

此外，连续添加的两条反向边具有相邻编号，因此有：

$$
\text{reverse}(i)=i\oplus 1
$$

其中 $\oplus$ 表示按位异或。后面的割边与割点算法将利用这一性质跳过父边的反向边，因此必须使用 `addUndirectedEdge` 添加无向边，不能分别在其他插边操作之间随意插入这两条反向边。

转置图是将原图中的每条边 $u\to v$ 反转为 $v\to u$ 后得到的图。`transpose()` 通过遍历原图的所有边并反向添加，构造转置图，时间复杂度为 $O(V+E)$。

# 广度优先搜索（BFS）

广度优先搜索（Breadth-First Search，BFS）从起点出发，按照距离起点的边数递增的顺序访问顶点。

BFS 使用队列维护待访问的顶点。每次取出队首顶点，访问其尚未发现的邻接点，并将这些邻接点加入队尾。

由于队列先进先出，距离起点较近的顶点会先于距离较远的顶点被处理。因此，对于无权图，BFS 第一次发现顶点时，就得到了从起点到该顶点的最短路径距离。

```cpp
std::vector<int> bfs(const GraphForwardStar& graph, int start) {
    std::vector<bool> visited(graph.vertex_count, false);
    std::queue<int> q;
    std::vector<int> order;

    visited[start] = true;
    q.push(start);

    while (!q.empty()) {
        int u = q.front();
        q.pop();
        order.push_back(u);

        for (int i = graph.head[u]; i != -1; i = graph.edges[i].next) {
            int v = graph.edges[i].to;
            if (!visited[v]) {
                visited[v] = true;
                q.push(v);
            }
        }
    }

    return order;
}
```

把顶点加入队列时就标记为已访问，而不是等到出队时再标记，可以避免同一顶点被重复加入队列。

上述实现只访问从 `start` 可达的顶点。如果需要遍历整个图，则应从每个尚未访问的顶点重新启动 BFS，直到所有顶点都被处理。

BFS 的时间复杂度为 $O(V+E)$，辅助空间复杂度为 $O(V)$。

# 深度优先搜索（DFS）

深度优先搜索（Depth-First Search，DFS）沿一条路径尽可能深入，直到无法继续访问未访问的顶点时再回溯。

递归实现中，函数调用栈自然承担了记录当前搜索路径和回溯位置的作用。

```cpp
std::vector<int> dfs(const GraphForwardStar& graph, int start) {
    std::vector<bool> visited(graph.vertex_count, false);
    std::vector<int> order;

    std::function<void(int)> visit = [&](int u) {
        visited[u] = true;
        order.push_back(u);

        for (int i = graph.head[u]; i != -1; i = graph.edges[i].next) {
            int v = graph.edges[i].to;
            if (!visited[v]) {
                visit(v);
            }
        }
    };

    visit(start);
    return order;
}
```

DFS 的访问顺序取决于邻接点的遍历顺序。对于链式前向星，边按后加入的优先遍历，因此不同的边插入顺序可能产生不同的 DFS 序列。

DFS 常用于环检测、拓扑排序、割边与割点、强连通分量等图算法。需要注意，普通 DFS 的前序访问顺序本身并不直接等于拓扑序；对于拓扑排序，通常需要利用 DFS 的后序顺序。

若需要遍历整个图，同样需要从每个尚未访问的顶点启动 DFS。DFS 的时间复杂度为 $O(V+E)$，辅助空间复杂度为 $O(V)$，其中包括访问标记和最坏情况下的递归调用栈。

递归实现更直观，但当图的搜索深度很大时，递归调用栈可能溢出。对于这类场景，可以使用显式栈模拟递归过程。

# 拓扑排序

拓扑排序（topological sort）只适用于有向无环图（Directed Acyclic Graph，DAG）。

拓扑排序将所有顶点排列成一个序列，使每条有向边 $u\to v$ 都满足 $u$ 出现在 $v$ 之前。直观上，若 $u\to v$ 表示任务 $u$ 必须先于任务 $v$ 完成，那么拓扑排序给出了满足所有先后约束的执行顺序。

DAG 的拓扑序不一定唯一。当多个顶点同时满足入度为 $0$ 时，它们之间没有必须优先处理的约束，可以选择不同的处理顺序。

## Kahn 算法

Kahn 算法反复选择入度为 $0$ 的顶点，将其加入结果序列，并删除它的所有出边。

删除边 $u\to v$ 相当于移除 $v$ 的一个前驱，因此需要将 `indegree[v]` 减一。当某个顶点的入度降为 $0$ 时，说明它的所有前驱都已处理，可以将其加入队列。

```cpp
std::vector<int> topologicalSort(const GraphForwardStar& graph) {
    int n = graph.vertex_count;
    std::vector<int> indegree(n, 0);

    for (const auto& edge : graph.edges) {
        indegree[edge.to]++;
    }

    std::queue<int> q;
    for (int u = 0; u < n; u++) {
        if (indegree[u] == 0) {
            q.push(u);
        }
    }

    std::vector<int> order;

    while (!q.empty()) {
        int u = q.front();
        q.pop();
        order.push_back(u);

        for (int i = graph.head[u]; i != -1; i = graph.edges[i].next) {
            int v = graph.edges[i].to;
            if (--indegree[v] == 0) {
                q.push(v);
            }
        }
    }

    // 不能处理所有顶点，说明图中存在有向环。
    if (static_cast<int>(order.size()) != n) {
        return {};
    }

    return order;
}
```

算法时间复杂度为 $O(V+E)$，辅助空间复杂度为 $O(V)$。

**正确性要点：** 每次加入结果序列的顶点入度都为 $0$，因而它没有尚未处理的前驱，不会违反任何边所要求的先后顺序。

如果最终序列的长度小于 $V$，说明还有顶点无法被处理。此时，剩余子图中每个顶点的入度都大于等于 $1$。沿着入边不断向前追溯，最终必然重复遇到某个顶点，从而形成有向环。因此，算法无法处理全部顶点当且仅当图中存在有向环。

这里用空 `vector` 表示存在环。实际项目中，若需要区分“空图的合法拓扑序”和“拓扑排序失败”，可以额外返回状态标记。

> [!note] 拓扑序不唯一
>
> 当队列中同时存在多个入度为 $0$ 的顶点时，选择顺序不同可能得到不同的合法拓扑序。若队列在整个过程中始终只有一个可选顶点，则拓扑序唯一。

## DFS 后序法

对于 DFS，顶点的前序是指首次访问该顶点时记录的顺序；后序则是指该顶点的所有邻接点处理完成、即将返回上一层时记录的顺序。

在 DAG 中，若存在边 $u\to v$，则 DFS 完成 $v$ 的时间一定早于完成 $u$ 的时间。因此，沿 DFS 后序排列时，$v$ 会先于 $u$ 出现；将后序整体反转，便可得到满足所有边约束的拓扑序。

如果 DFS 过程中遇到一条指向当前搜索路径中顶点的边，则存在有向环，拓扑排序失败。这里使用三个状态：

- `0`：尚未访问。
- `1`：正在访问，即位于当前 DFS 路径中。
- `2`：已经完成，所有出边均已处理。

```cpp
std::vector<int> topologicalSortByDfs(const GraphForwardStar& graph) {
    int n = graph.vertex_count;
    std::vector<int> state(n, 0);
    std::vector<int> order;
    bool acyclic = true;

    std::function<void(int)> visit = [&](int u) {
        state[u] = 1;

        for (int i = graph.head[u]; i != -1; i = graph.edges[i].next) {
            int v = graph.edges[i].to;

            if (state[v] == 1) {
                acyclic = false;
                return;
            }

            if (state[v] == 0) {
                visit(v);
                if (!acyclic) {
                    return;
                }
            }
        }

        state[u] = 2;
        order.push_back(u);
    };

    // 不能假定全图只有一个 DFS 起点。
    for (int u = 0; u < n; u++) {
        if (state[u] == 0) {
            visit(u);
            if (!acyclic) {
                return {};
            }
        }
    }

    std::reverse(order.begin(), order.end());
    return order;
}
```

算法时间复杂度为 $O(V+E)$，辅助空间复杂度为 $O(V)$。

外层循环保证每个顶点最终都被处理，包括无法从某个指定起点到达的顶点。若图中存在环，DFS 会遇到指向状态为 `1` 的顶点的边，从而判定拓扑排序失败。

前面的普通 DFS 记录的是前序访问顺序，不能直接用于拓扑排序。这里必须等到顶点的所有后继顶点处理完毕之后再记录它，也就是使用后序，然后将整个序列反转。

# 割边与割点

割边（bridge）是无向图中删除后会使连通分量数增加的边。

割点（articulation point）是无向图中删除后会使连通分量数增加的顶点。

求割边与割点时，需要考虑无向图中的所有连通分量。下面使用 DFS 和 `tin`、`low` 数组在线性时间内求出全部割边与割点。

## Tarjan 算法

对无向图进行 DFS，定义：

- `tin[u]`：首次访问顶点 $u$ 时的时间戳。时间戳越小，说明顶点越早被发现。
- `low[u]`：从 $u$ 的 DFS 子树出发，沿 DFS 树边向下，再沿至多一条非树边返回 $u$ 或其祖先时，能够到达的最小时间戳。

`low` 可以通过递归关系计算：

$$
\operatorname{low}[u]
=
\min\left(
\operatorname{tin}[u],
\min_{\text{回边 }u\to v}\operatorname{tin}[v],
\min_{\text{树边 }u\to w}\operatorname{low}[w]
\right)
$$

其中，回边指无向图中连接 DFS 树上的顶点与其祖先、但不属于 DFS 树的边。实现时需要跳过当前树边对应的反向边，避免将它误认为回边。

对于 DFS 树边 $u\to v$，有以下判断条件：

- 若 $\operatorname{low}[v]>\operatorname{tin}[u]$，则 $(u,v)$ 是割边。因为 $v$ 的 DFS 子树无法通过其他边到达 $u$ 或其祖先，删除该边会将这棵子树与其余部分分开。
- 若 $u$ 不是 DFS 树根，且 $\operatorname{low}[v]\ge\operatorname{tin}[u]$，则 $u$ 是割点。因为 $v$ 的 DFS 子树无法通过其他边到达 $u$ 的祖先，删除 $u$ 会使该子树与其余部分分离。
- 若 $u$ 是 DFS 树根，则当且仅当它有至少两个 DFS 子树时，它才是割点。根没有祖先，因此不能直接使用非根顶点的判断条件。

注意，割边和割点的判定条件一个使用严格大于号，另一个使用大于等于号。这是因为，如果 $\operatorname{low}[v]=\operatorname{tin}[u]$，说明 $v$ 的子树可以通过其他边回到 $u$，所以树边 $(u,v)$ 不是割边；但它仍无法绕过 $u$ 到达 $u$ 的祖先，因此 $u$ 仍可能是割点。

```cpp
struct CutResult {
    std::vector<std::pair<int, int>> bridges;
    std::vector<bool> articulation;
};

CutResult findBridgesAndArticulationPoints(
    const GraphForwardStar& graph) {
    int n = graph.vertex_count;
    std::vector<int> tin(n, -1);
    std::vector<int> low(n);
    std::vector<bool> articulation(n, false);
    std::vector<std::pair<int, int>> bridges;
    int timer = 0;

    // parent_edge 是从当前顶点返回父顶点的那条反向边编号。
    std::function<void(int, int)> dfs = [&](int u, int parent_edge) {
        tin[u] = low[u] = timer++;
        int child_count = 0;

        for (int i = graph.head[u]; i != -1; i = graph.edges[i].next) {
            if (i == parent_edge) {
                continue;
            }

            int v = graph.edges[i].to;

            if (tin[v] == -1) {
                child_count++;
                dfs(v, i ^ 1);
                low[u] = std::min(low[u], low[v]);

                if (low[v] > tin[u]) {
                    bridges.push_back({u, v});
                }

                if (parent_edge != -1 && low[v] >= tin[u]) {
                    articulation[u] = true;
                }
            } else {
                low[u] = std::min(low[u], tin[v]);
            }
        }

        // DFS 树根需要单独判断。
        if (parent_edge == -1 && child_count > 1) {
            articulation[u] = true;
        }
    };

    // 无向图可能不连通，需要处理每个连通分量。
    for (int u = 0; u < n; u++) {
        if (tin[u] == -1) {
            dfs(u, -1);
        }
    }

    return {bridges, articulation};
}
```

该实现利用边编号准确跳过父边的反向边，因此可以正确处理重边。这里的重边是指同一对顶点之间存在多条不同的无向边；若输入图可能包含重边，应确保每条无向边仍通过 `addUndirectedEdge` 成对存储。

算法时间复杂度为 $O(V+E)$。不计输入图本身，辅助空间复杂度为 $O(V)$，其中包括时间戳、`low` 数组和递归调用栈；若将图的存储空间也计算在内，总空间复杂度为 $O(V+E)$。

# 强连通分量

强连通分量（Strongly Connected Component，SCC）是有向图中的极大顶点集合，使得集合内任意两个顶点之间都存在有向路径。这里的极大性意味着：不能再加入其他顶点而仍然保持强连通。

求强连通分量时，通常使用 Kosaraju 算法或 Tarjan 算法，两者的时间复杂度均为 $O(V+E)$。

## Kosaraju 算法

Kosaraju 算法需要进行两遍 DFS，并使用原图和转置图。

**第一遍 DFS：** 遍历原图的所有顶点。当一个顶点的所有出边都处理完毕时，将其加入后序序列 `order`。最后得到的序列按完成时间递增排列。

**第二遍 DFS：** 构造原图的转置图，按照第一遍 DFS 完成时间的逆序，也就是 `order` 的反向顺序，在转置图中进行 DFS。每次 DFS 访问到的顶点构成一个强连通分量。

```cpp
std::vector<std::vector<int>> stronglyConnectedComponents(
    const GraphForwardStar& graph) {
    int n = graph.vertex_count;
    std::vector<bool> visited(n, false);
    std::vector<int> order;

    // 第一遍：按 DFS 完成时间记录顶点。
    std::function<void(int)> dfs1 = [&](int u) {
        visited[u] = true;

        for (int i = graph.head[u]; i != -1; i = graph.edges[i].next) {
            int v = graph.edges[i].to;
            if (!visited[v]) {
                dfs1(v);
            }
        }

        order.push_back(u);
    };

    for (int u = 0; u < n; u++) {
        if (!visited[u]) {
            dfs1(u);
        }
    }

    GraphForwardStar transposed = graph.transpose();
    visited.assign(n, false);
    std::vector<std::vector<int>> components;

    // 第二遍：按完成时间的逆序搜索转置图。
    std::function<void(int)> dfs2 = [&](int u) {
        visited[u] = true;
        components.back().push_back(u);

        for (int i = transposed.head[u]; i != -1; i = transposed.edges[i].next) {
            int v = transposed.edges[i].to;
            if (!visited[v]) dfs2(v);
        }
    };

    for (auto it = order.rbegin(); it != order.rend(); ++it) {
        if (!visited[*it]) {
            components.emplace_back();
            dfs2(*it);
        }
    }

    return components;
}
```

算法时间复杂度为 $O(V+E)$，辅助空间复杂度为 $O(V)$，包括访问标记、后序序列和 DFS 调用栈。构造转置图需要 $O(V+E)$ 的额外存储，因此连同图的存储计算时，总空间复杂度为 $O(V+E)$。

**为什么第二遍 DFS 得到的每个集合都是一个强连通分量？**

可以把每个强连通分量看成一个整体。将每个强连通分量缩成一个顶点后，得到的缩点图一定是 DAG：如果缩点图中存在有向环，那么环上的各个分量就可以互相到达，它们实际上应当属于同一个强连通分量。

第一遍 DFS 的完成时间为第二遍的搜索提供了关键顺序：按照完成时间逆序处理转置图时，DFS 会先进入缩点图中适合首先处理的分量，而不会沿着转置图的边误入尚未处理的另一个分量。因此，每次 DFS 恰好找出一个完整的强连通分量。

## Tarjan 算法

Tarjan 的 SCC 算法只需要遍历原图一次，不需要构造转置图。

算法维护三个主要结构：

- `index[u]`：顶点 $u$ 首次访问时分配的编号。值为 `-1` 表示尚未访问。
- `low_link[u]`：从 $u$ 的 DFS 子树出发，沿 DFS 树边向下，并通过至多一条指向当前 SCC 栈中顶点的边能够关联到的最小访问编号。
- `component_stack`：存储已经访问、但尚未归入某个完整 SCC 的顶点。`on_stack[u]` 用于判断顶点是否仍在这个栈中。

处理一条边 $u\to v$ 时，分为三种情况：

- 若 $v$ 尚未访问，则递归访问 $v$，返回后用 `low_link[v]` 更新 `low_link[u]`。
- 若 $v$ 已经访问且仍在 SCC 栈中，则可以用 `index[v]` 更新 `low_link[u]`。
- 若 $v$ 已经不在 SCC 栈中，则忽略这条边对 `low_link[u]` 的影响，因为 $v$ 已属于一个确定的 SCC，不能再用于合并当前尚未完成的分量。

当 $\operatorname{low\_link}[u]=\operatorname{index}[u]$ 时，说明 $u$ 是一个 SCC 的根。此时从 `component_stack` 栈顶不断弹出顶点，直到弹出 $u$ 为止，这些顶点共同构成一个强连通分量。

```cpp
std::vector<std::vector<int>> stronglyConnectedComponentsByTarjan(
    const GraphForwardStar& graph) {
    int n = graph.vertex_count;
    std::vector<int> index(n, -1);
    std::vector<int> low_link(n);
    std::vector<bool> on_stack(n, false);
    std::vector<int> component_stack;
    std::vector<std::vector<int>> components;
    int timer = 0;

    std::function<void(int)> dfs = [&](int u) {
        index[u] = low_link[u] = timer++;
        component_stack.push_back(u);
        on_stack[u] = true;

        for (int i = graph.head[u]; i != -1; i = graph.edges[i].next) {
            int v = graph.edges[i].to;

            if (index[v] == -1) {
                dfs(v);
                low_link[u] = std::min(low_link[u], low_link[v]);
            } else if (on_stack[v]) {
                low_link[u] = std::min(low_link[u], index[v]);
            }
        }

        // u 是一个 SCC 的根，将该分量从栈中取出。
        if (low_link[u] == index[u]) {
            components.emplace_back();

            while (true) {
                int v = component_stack.back();
                component_stack.pop_back();
                on_stack[v] = false;
                components.back().push_back(v);

                if (v == u) {
                    break;
                }
            }
        }
    };

    for (int u = 0; u < n; u++) {
        if (index[u] == -1) dfs(u);
    }

    return components;
}
```

Tarjan SCC 算法的时间复杂度为 $O(V+E)$。不计输入图本身，辅助空间复杂度为 $O(V)$；包含图的存储时，总空间复杂度为 $O(V+E)$。

与 Kosaraju 算法相比，Tarjan 算法不需要构造转置图，也只需要进行一遍 DFS，但需要维护 `low_link`、SCC 栈以及栈内状态。两种算法都适用于有向图，实际选择时可以根据代码可读性、实现需求和栈深限制决定。
