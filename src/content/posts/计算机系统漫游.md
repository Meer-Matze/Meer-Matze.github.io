# 第一章 计算机系统漫游

**计算机系统**由硬件和系统软件组成，它们共同运行应用程序。

不同系统的实现方式会变化，但核心概念相近。理解这些概念，有助于编写更可靠、更高效、更安全的程序。

本章以 `hello` 程序为线索，介绍程序从源代码到运行结果所经历的过程。

> [!important] 本章目标
> 建立计算机系统的整体模型，理解编译系统、硬件、操作系统、网络、存储层次、并发和抽象之间的关系。

在 Kernighan 和 Ritchie 的 C 语言经典教材中，他们通过 hello 程序向读者介绍 C。尽管 hello 程序非常简单，但为了让它运行，系统的每个主要组成部分都需要协调工作——本书的目的就是帮助理解执行 hello 程序时系统发生了什么、为什么会这样。

```c
#include <stdio.h>
int main()
{
    printf("hello, world\n");
    return 0;
}
```

我们通过跟踪 hello 程序的生命周期来开始对系统的学习——从它被程序员创建开始，到在系统上运行、输出消息、终止。沿着这条生命周期，简要介绍逐步出现的关键概念、专业术语和组成部分，后面的章节将围绕这些内容展开。

# 第一部分 程序与编译系统

## 1.1 信息就是位与上下文

hello 程序的生命周期从一个**源程序**开始——程序员用编辑器创建并保存的文本文件 `hello.c`。源程序本质上是一个由 0 和 1 组成的位（比特）序列，8 个位组成一字节，每字节表示程序中的某些文本字符。

大部分现代计算机系统使用 ASCII 表示文本字符，每个字符对应一个唯一的单字节整数值。`hello.c` 第一个字节的整数值是 35，对应字符 `#`；第二个字节整数值是 105，对应字符 `i`；每个文本行以一个看不见的换行符 `\n` 结束，对应整数值 10。像 `hello.c` 这样只由 ASCII 字符构成的文件称为**文本文件**，其他文件都称为**二进制文件**。

> [!note] 字符编码
> 也有用于表示非英语文本的其他编码方式，具体讨论参见 2.1.4 节。

`hello.c` 的表示方法说明了一个基本思想：系统中所有的信息——磁盘文件、内存中的程序、内存中的用户数据、网络上传送的数据，都是由一串比特表示的。区分不同数据对象的唯一方法是读到这些数据时的**上下文**——同样的字节序列在不同上下文中可能表示整数、浮点数、字符串或机器指令。作为程序员，需要了解数字的机器表示方式，因为它们是对真值的有限近似，有时会有意想不到的行为，这方面的基本原理将在第二章详细描述。

> [!note] 编程语言的起源
> C 语言由贝尔实验室的 Dennis Ritchie 于 1969–1973 年间创建。ANSI 于 1989 年发布 ANSI C 标准，之后标准化工作由 ISO 负责。这些标准定义了 C 语言和 C 标准库。Kernighan 和 Ritchie 的经典著作通常称为"K&R"。Ritchie 将 C 形容为"古怪的、有缺陷的，但同时也是一个巨大的成功"。
>
> C 语言的几个特点：
>
> - **与 Unix 关系密切**：C 从一开始就用于 Unix，Unix 内核、工具和库大量使用 C，因此 C 易于随 Unix 移植
> - **语言小而简单**：设计简洁，易于学习和移植
> - **面向实践**：最初用于实现 Unix，后来广泛用于其他程序
>
> C 适合系统级编程，也能用于应用级程序。它的指针容易造成错误，也没有直接提供类、对象和异常等抽象，C++ 和 Java 等语言弥补了这些不足。

## 1.2 程序被其他程序翻译成不同的格式

为了在系统上运行 `hello.c`，每条 C 语句都必须被其他程序转化为一系列低级**机器语言**指令，然后按**可执行目标程序**（也叫可执行目标文件）的格式打包，以二进制磁盘文件形式存放。

在 Unix 系统上，从源文件到目标文件的转化由**编译器驱动程序**完成：

```bash
linux> gcc -o hello hello.c
```

GCC 编译器驱动程序读取源文件 `hello.c`，翻译成可执行目标文件 `hello`。这个过程分四个阶段完成，执行这四个阶段的程序——**预处理器**、**编译器**、**汇编器**、**链接器**——一起构成**编译系统**（compilation system）：

- **预处理阶段**：预处理器（cpp）根据以 `#` 开头的命令修改原始 C 程序。例如 `#include <stdio.h>` 告诉预处理器读取系统头文件 `stdio.h` 的内容并插入程序文本，结果得到另一个 C 程序，通常以 `.i` 为扩展名
- **编译阶段**：编译器（cc1）将文本文件 `hello.i` 翻译成文本文件 `hello.s`，包含一个汇编语言程序：

  ```asm
  main:
      subq $8, %rsp
      movl $.LC0, %edi
      call puts
      movl $0, %eax
      addq $8, %rsp
      ret
  ```

  每条语句都以文本格式描述一条低级机器语言指令。汇编语言很有用，因为它为不同高级语言的不同编译器提供了通用的输出语言——例如 C 编译器和 Fortran 编译器产生的输出文件用的是同一种汇编语言。

- **汇编阶段**：汇编器（as）将 `hello.s` 翻译成机器语言指令，打包成**可重定位目标文件**（relocatable object file）`hello.o`——二进制文件，不能直接按文本阅读
- **链接阶段**：`hello` 调用的 `printf` 来自 C 标准库，链接器（ld）把 `hello.o` 与所需的库目标模块合并，生成可执行目标文件 `hello`

> [!note] GNU 项目
> GCC 是 GNU 项目开发的工具之一。GNU 项目由 Richard Stallman 于 1984 年发起，目标是构建可自由修改和传播的类 Unix 系统。GNU 环境包含 Emacs、GCC、GDB、汇编器、链接器和二进制工具。Linux 内核由 Linux 项目独立开发，GNU 工具为 Linux 提供了重要的用户空间环境。

# 第二部分 运行 hello 程序

## 1.3 处理器读取并解释内存中的指令

`hello.c` 被编译系统翻译成可执行目标文件 `hello` 并存放在磁盘上。要在 Unix 系统上运行它，把文件名输入到 shell 中：

```
linux> ./hello
hello, world
linux>
```

shell 是命令行解释器，输出提示符、等待命令行、执行命令。若命令行第一个单词不是内置 shell 命令，shell 就假设这是可执行文件名，加载并运行它。

### 1.3.1 系统的硬件组成

#### 1. 总线

贯穿整个系统的一组电子管道称为**总线**，携带信息字节并在各部件间传递。总线通常被设计成传送定长的字节块，即**字**（word）；字中的字节数（字长）是基本系统参数，各系统不尽相同——现在的大多数机器字长要么是 4 字节（32 位），要么是 8 字节（64 位）。

#### 2. I/O 设备

I/O 设备是系统与外部世界的联系通道：键盘、鼠标（用户输入）、显示器（用户输出）、磁盘驱动器（长期存储）。每个 I/O 设备通过**控制器**或**适配器**与 I/O 总线相连——控制器是设备本身或主板上的芯片组，适配器是插在主板插槽上的卡，两者的功能都是在 I/O 总线和 I/O 设备之间传递信息。

#### 3. 主存

**主存**是临时存储设备，处理器执行程序时用来存放程序和数据。物理上主存由一组**动态随机存取存储器**（DRAM）芯片组成；逻辑上，存储器是一个线性的字节数组，每字节都有唯一的地址（从零开始）。在运行 Linux 的 x86-64 机器上，`short` 类型需要 2 字节，`int` 和 `float` 需要 4 字节，`long` 和 `double` 需要 8 字节。

#### 4. 处理器

**中央处理单元**（CPU，简称处理器）是解释（执行）主存中指令的引擎。处理器核心是一个字长大小的存储设备**寄存器**，称为**程序计数器**（PC），在任何时刻都指向主存中的某条机器语言指令。

> [!note] PC 的两种含义
> PC 也可表示"个人计算机"，两者的含义可由上下文区分。

从通电到断电，处理器不断执行 PC 指向的指令、再更新 PC 指向下一条指令。处理器按照**指令集架构**决定的简单模型操作：指令按严格顺序执行，每条指令的执行包含一系列步骤——取指令、解释指令中的位、执行简单操作、更新 PC（不一定指向内存中相邻的指令）。

这些简单操作围绕主存、**寄存器文件**（由若干单字长寄存器组成的小存储设备）和**算术/逻辑单元**（ALU，计算新数据和地址值）进行：

- **加载**：从主存复制一个字节或字到寄存器
- **存储**：从寄存器复制一个字节或字到主存
- **操作**：将两个寄存器内容送入 ALU，计算结果写入寄存器
- **跳转**：从指令中提取地址，复制到 PC

现代处理器使用复杂机制加速执行，因此需要把处理器的**指令集架构**（描述每条机器代码指令的效果）和**微体系结构**（描述处理器实际如何实现）区分开——第三章研究机器代码时考虑指令集架构提供的抽象，第四章详细介绍处理器实际如何实现，第五章用模型说明现代处理器如何工作以预测和优化程序性能。第六章介绍磁盘等 I/O 设备的工作原理，第十章介绍如何用 Unix I/O 接口在应用程序中访问设备。

### 1.3.2 运行 hello 程序

用户键入 `./hello` 并回车，shell 将字符读入寄存器再存入内存。shell 执行一系列指令加载可执行的 `hello` 文件，把 `hello` 目标文件中的代码和数据从磁盘复制到主存——包括最终会被输出的字符串 `"hello, world\n"`。利用**直接存储器存取**（DMA，第六章讨论），数据可以不通过处理器直接从磁盘到达主存。

一旦目标文件 `hello` 的代码和数据被加载到主存，处理器就开始执行 `hello` 程序 `main` 函数中的机器语言指令：这些指令把 `"hello, world\n"` 字符串中的字节从主存复制到寄存器文件，再从寄存器文件复制到显示设备，最终显示在屏幕上。

# 第三部分 存储层次与操作系统

## 1.4 高速缓存至关重要

hello 程序的机器指令最初在磁盘上，加载时复制到主存，运行时又从主存复制到处理器；数据串 `"hello, world\n"` 同样经历磁盘 → 主存 → 显示设备的复制。从程序员角度看，这些复制是开销，减慢了程序"真正"的工作，因此系统设计者的一个主要目标就是让这些复制操作尽可能快。

根据机械原理，较大的存储设备比较小的运行得慢，快速设备的造价也远高于同类低速设备：典型系统上磁盘驱动器可能比主存大 1000 倍，但处理器从磁盘读取一个字的时间开销比从主存读取大 1000 万倍。类似地，典型寄存器文件只存储几百字节，主存可存放几十亿字节，但处理器从寄存器文件读数据比从主存读几乎快 100 倍——且这种处理器与主存之间的差距还在持续增大，因为加快处理器速度比加快主存速度容易和便宜得多。

针对这种差异，系统设计者采用更小更快的存储设备——**高速缓存存储器**（cache memory），作为暂时的集结区域，存放处理器近期可能需要的信息。位于处理器芯片上的 L1 高速缓存容量可达数万字节，访问速度几乎和访问寄存器文件一样快；容量数十万到数百万字节的 L2 高速缓存通过特殊总线连接到处理器，访问时间比 L1 长 5 倍，但仍比访问主存快 5~10 倍。L1 和 L2 高速缓存用**静态随机访问存储器**（SRAM）技术实现；较新的系统甚至有三级高速缓存（L1、L2、L3）。系统能获得又大又快的存储器，原因是利用了高速缓存的**局部性原理**——程序倾向于访问局部区域里的数据和代码，让高速缓存存放可能经常访问的数据，大部分内存操作就能在快速的高速缓存中完成。

意识到高速缓存存在的应用程序员，能利用它将程序性能提高一个数量级——第六章详细介绍这些设备以及如何利用它们。

## 1.5 存储设备形成层次结构

在处理器和一个较大较慢的设备（如主存）之间插入一个更小更快的存储设备（如高速缓存）的想法已成为普遍观念——每个计算机系统的存储设备都被组织成**存储器层次结构**：从上至下，访问速度越来越慢、容量越来越大、每字节造价越来越便宜。寄存器文件位于层次结构顶部（第 0 级 L0），三层高速缓存 L1 到 L3 占据第 1 到第 3 层，主存在第 4 层，依此类推。

存储器层次结构的主要思想是：上一层存储器作为低一层存储器的高速缓存——寄存器文件是 L1 的高速缓存，L1 是 L2 的高速缓存，L2 是 L3 的高速缓存，L3 是主存的高速缓存，主存又是磁盘的高速缓存。在某些具有分布式文件系统的网络系统中，本地磁盘就是存储在其他系统磁盘上数据的高速缓存。程序员同样可以利用对整个存储器层次结构的理解来提高程序性能，第六章将详细讨论。

## 1.6 操作系统管理硬件

shell 加载和运行 hello 程序、hello 程序输出消息时，都没有直接访问键盘、显示器、磁盘或主存，而是依靠操作系统提供的服务。可以把操作系统看成应用程序和硬件之间插入的一层软件——所有应用程序对硬件的操作尝试都必须通过操作系统。

操作系统有两个基本功能：（1）防止硬件被失控的应用程序滥用；（2）向应用程序提供简单一致的机制来控制复杂又通常大不相同的低级硬件设备。操作系统通过**进程**、**虚拟内存**、**文件**这三个基本抽象概念实现这两个功能——文件是对 I/O 设备的抽象，虚拟内存是对主存和磁盘 I/O 设备的抽象，进程是对处理器、主存和 I/O 设备的抽象。

> [!note] Unix、POSIX 和标准 Unix 规范
> 20 世纪 60 年代，IBM OS/360 和 Multics 等大型操作系统兴起。贝尔实验室于 1969 年退出 Multics 项目后，Ken Thompson、Dennis Ritchie、Doug McIlroy 和 Joe Ossanna 在 DEC PDP-7 上开发了更小的 Unix，1973 年用 C 重写，1974 年开始正式发布。
>
> 贝尔实验室以慷慨的条件向学校提供源代码，Unix 在大专院校获得了很多支持并持续发展。最有影响的工作发生在 20 世纪 70 年代晚期到 80 年代早期的加州大学伯克利分校，研究人员增加了虚拟内存和 Internet 协议，称为 Unix 4.xBSD（Berkeley Software Distribution）；贝尔实验室同时发布 System V Unix；Sun Microsystems 的 Solaris 等其他厂商版本从这些原始版本衍生而来。
>
> 20 世纪 80 年代中期，Unix 厂商增加了许多不兼容特性，IEEE 随后推动 Unix 标准化，这些标准后来称为 POSIX，涵盖系统调用接口、shell、工具、线程和网络编程。标准 Unix 规范则提供了另一套统一标准。

### 1.6.1 进程

hello 这样的程序运行时，操作系统提供一种假象——好像系统上只有这个程序在运行，独占使用处理器、主存和 I/O 设备。**进程**是操作系统对正在运行的程序的抽象，是计算机科学中最重要和最成功的概念之一；多个进程可以同时存在，每个都像在独占使用硬件。

**并发运行**指多个进程的指令交错执行：单处理器系统通过上下文切换实现并发，多核系统可以真正并行执行多个进程（本节只讨论单处理器系统，多处理器见 1.8.2 节）。

操作系统保持跟踪进程运行所需的所有状态信息，即**上下文**（PC 和寄存器文件的当前值、主存内容等）。任何时刻，单处理器系统只能执行一个进程的代码；操作系统决定把控制权从当前进程转移到新进程时，会进行**上下文切换**——保存当前进程上下文、恢复新进程上下文、传递控制权，新进程从上次停止的地方继续。

示例场景有两个并发进程：shell 进程和 hello 进程。最初只有 shell 进程运行，等待命令行输入；用户要求运行 hello 程序时，shell 通过调用**系统调用**（一种专门的函数）把控制权传递给操作系统——操作系统保存 shell 进程的上下文，创建新的 hello 进程及其上下文，把控制权传给新进程；hello 进程终止后，操作系统恢复 shell 进程的上下文并传回控制权。

从一个进程到另一个进程的转换由操作系统**内核**（kernel）管理——内核是操作系统代码常驻主存的部分。应用程序需要操作系统的某些操作（如读写文件）时，执行一条特殊的系统调用指令，将控制权传给内核，内核执行请求的操作后返回应用程序。注意内核不是一个独立的进程，而是系统管理全部进程所用代码和数据结构的集合。实现进程这个抽象概念需要低级硬件和操作系统软件的紧密合作，第八章将揭示这项工作的原理，以及应用程序如何创建和控制它们的进程。

### 1.6.2 线程

现代进程可以包含多个**线程**，线程运行在进程上下文中，共享代码和全局数据。线程通常比进程更容易共享数据，切换开销也更低；多核系统还能让多个线程并行运行。第十二章将详细讨论线程并发。

### 1.6.3 虚拟内存

**虚拟内存**是一个抽象概念，为每个进程提供假象——好像每个进程都独占使用主存。每个进程看到的内存是一致的，称为**虚拟地址空间**。在 Linux 中，地址空间最上面的区域保留给操作系统的代码和数据（对所有进程都一样），底部区域存放用户进程定义的代码和数据（地址从下往上增大）。

从最低地址开始，依次是：

| 区域           | 说明                                                 | 详见                 |
| -------------- | ---------------------------------------------------- | -------------------- |
| 程序代码和数据 | 由可执行目标文件初始化                               | 第七章（链接和加载） |

虚拟内存的运作需要硬件和操作系统软件精密复杂的交互，包括对处理器生成的每个地址的硬件翻译。基本思想是把一个进程虚拟内存的内容存储在磁盘上，用主存作为磁盘的高速缓存——第九章将解释它如何工作、为什么对现代系统的运行如此重要。

### 1.6.4 文件

**文件**就是字节序列，仅此而已。每个 I/O 设备——磁盘、键盘、显示器、甚至网络——都可以看成文件；系统中所有输入输出都通过一小组称为 Unix I/O 的系统函数调用读写文件来实现。

文件这个简单而精致的概念很强大，因为它向应用程序提供了统一的视图看待系统中各式各样的 I/O 设备——处理磁盘文件的程序员无须了解具体磁盘技术，同一个程序可以在使用不同磁盘技术的不同系统上运行。第十章将详细学习 Unix I/O。

# 第四部分 网络与系统主题

## 1.7 系统之间利用网络通信

现代系统经常通过网络和其他系统连接。从单个系统看，网络可视为一种 I/O 设备——系统从主存复制一串字节到网络适配器时，数据流经网络到达另一台机器；系统也可以读取从其他机器发来的数据并复制到自己的主存。

随着 Internet 等全球网络的出现，从一台主机复制信息到另一台已成为计算机系统最重要的用途之一——电子邮件、即时通信、万维网、FTP、telnet 都基于网络复制信息的功能。用 telnet 在远程主机上运行 hello 程序的典型步骤：在 telnet 客户端键入 `hello` 并回车，客户端把字符串发给 telnet 服务器；服务器从网络接收后传给远端 shell 程序；远端 shell 运行 hello 程序，把输出行返回给 telnet 服务器；服务器通过网络把输出串转发给客户端，客户端显示到本地终端上。这种客户端和服务器之间的交互在所有网络应用中都很典型，第十一章将学习如何构造网络应用程序，并创建一个简单的 Web 服务器。

## 1.8 重要主题

系统不仅仅是硬件，而是硬件和系统软件互相交织的集合体，它们必须共同协作才能运行应用程序。以下是几个贯穿计算机系统所有方面的重要概念。

### 1.8.1 Amdahl 定律

Amdahl 定律（Amdahl's law）的核心思想：对系统某部分加速，其对整体性能的影响取决于该部分的重要性和加速程度。设系统执行某应用程序需要时间 $T_{old}$，某部分所需时间占比为 $\alpha$，该部分性能提升比例为 $k$——该部分初始所需时间为 $\alpha T_{old}$，现在为 $(\alpha T_{old})/k$。总执行时间为：

$$T_{new}=(1-\alpha)T_{old}+\frac{\alpha T_{old}}{k}=T_{old}\left[(1-\alpha)+\frac{\alpha}{k}\right]$$

加速比 $S=T_{old}/T_{new}$ 为：

$$S=\frac{1}{(1-\alpha)+\alpha / k} \tag{1.1}$$

例如，若系统某部分占 60% 执行时间，该部分加速 3 倍，总体加速比为 $1/(0.4+0.6/3)=1.67$——总体加速比低于局部加速比，这就是 Amdahl 定律的核心：要显著加速系统，必须优化占比较大的部分。

> [!tip] 表示相对性能
> 性能提升最好用比例形式 $T_{old}/T_{new}$ 表示，如果有改进则比值大于 1，用后缀"×"表示，"2.2×"读作"2.2 倍"。也可以用百分比表示相对变化，但百分比的定义容易产生歧义——对较大的变化，"性能提升 2.2×"通常比"性能提升 120%"更清晰。

**练习**：卡车从爱达荷州 Boise 运土豆到明尼苏达州 Minneapolis，全程 2500 公里，限速内平均速度 100 公里/小时，需 25 小时。

A. 蒙大拿州取消限速，行程中 1500 公里可以 150 公里/小时行驶，整个行程的加速比是多少？

答案：$\alpha=1500/2500=0.6$，$k=150/100=1.5$。蒙大拿 1500 公里需 10 小时，其余 1000 公里也需 10 小时，加速比 $=25/(10+10)=1.25\times$（代入公式 1.1 验证：$1/(0.4+0.6/1.5)=1/0.8=1.25$，一致）。

B. 想让整个行程加速比达到 1.67×，通过蒙大拿必须以多快速度行驶？

答案：目标 $S=1.67$，$T_{new}=25/1.67 \approx 15$ 小时；蒙大拿以外仍需 10 小时，因此通过蒙大拿的时间为 5 小时，对应速度 $1500/5=300$ 公里/小时——对卡车来说太快了。

**练习**：只有 80% 的系统能被改进，改进多少（$k$ 取何值）才能让整体性能达到 2×？

答案：$S=2$，$\alpha=0.8$，代入求解：

$$2 = \frac{1}{(1-0.8)+0.8/k} \;\Rightarrow\; 0.4+1.6/k = 1.0 \;\Rightarrow\; k = 2.67$$

Amdahl 定律一个有趣的特殊情况是 $k \to \infty$——把系统某部分加速到该部分花费时间可忽略不计：

$$S_{\infty}=\frac{1}{(1-\alpha)} \tag{1.2}$$

例如若 60% 的系统能加速到不花时间的程度，净加速比仍只有 $1/0.4=2.5\times$。

Amdahl 定律描述了改善任何过程的一般原则，不限于计算机系统——优化公司制造成本、提高学生绩点都适用。在计算机世界里意义尤其重大，因为高比例因子的性能提升只有通过优化系统的大部分组件才能获得。

### 1.8.2 并发和并行

**并发**（concurrency）是一个通用概念，指一个同时具有多个活动的系统；**并行**（parallelism）指用并发使系统运行得更快。并行可以在计算机系统的多个抽象层次上运用，按由高到低的顺序有三个层次。

#### 1. 线程级并发

构建在进程抽象之上，能设计出同时有多个程序执行的系统；用线程，甚至能在一个进程中执行多个控制流。自 20 世纪 60 年代初期出现时间共享以来，计算机系统就开始支持并发执行——传统上这种并发是模拟出来的，通过计算机在正在执行的进程间快速切换实现。这种并发形式允许多用户同时与系统交互，也允许一个用户同时从事多个任务；但即使处理器要在多个任务间切换，大多数实际计算也是由一个处理器完成的，这种配置称为**单处理器系统**。

当构建由单操作系统内核控制的多处理器组成的系统时，得到**多处理器系统**——从 20 世纪 80 年代开始在大规模计算中就有这种系统，但直到最近随着多核处理器和**超线程**（hyperthreading）的出现才变得常见。

多核处理器是将多个 CPU（核）集成到一个集成电路芯片上：典型的 4 核处理器中，每个核都有自己的 L1、L2 高速缓存（L1 分两部分：一份存最近取到的指令、一份存数据），这些核共享更高层次的高速缓存及到主存的接口。业界预言芯片上能集成几十个、最终上百个核。

超线程（也称**同时多线程**，simultaneous multi-threading）允许一个 CPU 执行多个控制流：CPU 某些硬件（如程序计数器和寄存器文件）有多个备份，其他部分（如浮点运算单元）只有一份。常规处理器需要约 20000 个时钟周期做线程间转换，超线程处理器可以在单个周期基础上决定执行哪个线程——例如某线程等待数据装载到高速缓存时，CPU 可以继续执行另一个线程。Intel Core i7 处理器每核可执行两个线程，4 核系统可并行执行 8 个线程。

多处理器从两方面提高系统性能：一是减少执行多任务时模拟并发的需要；二是让程序（若以多线程方式书写）运行得更快。多核和超线程系统的出现极大激发了寻找利用硬件线程级并行性的编程方法的愿望。第十二章会更深入探讨并发，以及如何用并发提供处理器资源共享、让程序执行有更多并行。

#### 2. 指令级并行

较低抽象层次上，现代处理器能同时执行多条指令的属性称为**指令级并行**。早期微处理器如 1978 年的 Intel 8086 需要多个（通常 3~10 个）时钟周期执行一条指令；最近的处理器可以保持每时钟周期 2~4 条指令的执行速率——每条指令从开始到结束仍需约 20 个或更多周期，但处理器用很多技巧同时处理多达 100 条指令。第四章研究**流水线**（pipelining）——将执行一条指令的活动划分成不同步骤，组织成一系列并行操作的阶段，能达到接近一个时钟周期一条指令的执行速率。

若处理器能达到比一个周期一条指令更快的执行速率，称为**超标量**（superscalar）处理器，大多数现代处理器都支持。第五章描述超标量处理器的高级模型，帮助程序员理解性能、写出指令级并行性更高的代码。

#### 3. 单指令、多数据并行

最低层次上，许多现代处理器有特殊硬件，允许一条指令产生多个可并行执行的操作，称为**单指令、多数据**（SIMD）并行——例如较新几代 Intel 和 AMD 处理器能并行地对 8 对单精度浮点数做加法。SIMD 指令主要为提高处理影像、声音、视频数据应用的速度而设计；虽然有编译器尝试从 C 程序自动抽取 SIMD 并行性，但更可靠的方法是用编译器支持的特殊向量数据类型编程（如 GCC 支持的向量数据类型）。

### 1.8.3 计算机系统中抽象的重要性

抽象是计算机科学最重要的概念之一——为一组函数规定简单的应用程序接口（API）是良好的编程习惯，程序员无须了解内部工作即可使用；不同编程语言提供不同形式和等级的抽象支持（如 Java 类声明、C 语言函数原型）。

在处理器里，**指令集架构**提供了对实际处理器硬件的抽象——机器代码程序表现得就像运行在一个一次只执行一条指令的处理器上，底层硬件远比这复杂精细（并行执行多条指令），但总与这个简单有序的模型保持一致；只要执行模型一样，不同处理器实现能执行同样的机器代码，提供不同的开销和性能。

在操作系统层面，介绍了三个抽象：文件（I/O 设备的抽象）、虚拟内存（程序存储器的抽象）、进程（正在运行的程序的抽象）。再加一个新抽象——**虚拟机**，提供对整个计算机（包括操作系统、处理器、程序）的抽象。虚拟机思想是 IBM 在 20 世纪 60 年代提出的，但最近才显示出管理计算机方式上的优势，因为一些计算机必须能运行为不同操作系统（如 Windows、macOS、Linux）或同一操作系统不同版本设计的程序。

## 1.9 小结

计算机系统由硬件和系统软件组成，共同协作运行应用程序。计算机内部信息表示为一组组的位，依上下文有不同解释方式。程序被其他程序翻译成不同形式——从 ASCII 文本开始，被编译器和链接器翻译成二进制可执行文件。

处理器读取并解释存放在主存里的二进制指令。因为计算机花费大量时间在内存、I/O 设备和 CPU 寄存器间复制数据，系统中的存储设备被划分成层次结构——CPU 寄存器在顶部，接着是多层硬件高速缓存、DRAM 主存和磁盘存储器；层次模型中更高层的设备更快、单位比特造价更高，较高层可作为较低层的高速缓存。理解和运用存储层次结构的知识，程序员可以优化 C 程序的性能。

操作系统内核是应用程序和硬件之间的媒介，提供三个基本抽象：文件（I/O 设备的抽象）、虚拟内存（主存和磁盘的抽象）、进程（处理器、主存和 I/O 设备的抽象）。

网络提供了计算机系统之间通信的手段——从单个系统的角度看，网络就是一种 I/O 设备。
